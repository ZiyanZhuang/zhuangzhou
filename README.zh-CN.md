庄周是一个面向合成生物学、酶工程与计算化 DBTL 设计的自主科学智能体平台。
它以**跨学科知识图谱**为认知基础，以**多智能体系统**为决策中枢，以**蛋白质
设计、分子模拟和代谢网络分析**工具为执行能力，形成**思考→行动→观察→复盘→
再决策**的完整闭环，实现从酶分子活性位点设计到细胞代谢网络优化的跨尺度智能
工程。

产品方向是面向生物工程的专用 AI 科学家：一个把大模型规划能力与真实科学工具、
结构化生物学知识、通路推理、分子模拟、序列设计与可交付实验报告结合在一起的
领域智能体。AI 负责提议与协调，庄周负责计算、核验、记录与打包。

核心原则：科学结论应当来自明确的算法、结构化数据、数据库调用与可复现的工具
执行，而不是没有依据的文本生成。每一项设计决策都应可追溯、可审计、有证据链
支撑。

## 产品定位

庄周不是一个通用聊天机器人,也不只是一堆生物信息学脚本的合集。它被设计成一个
面向 DBTL 闭环的领域专用 AI 科学家:

```text
用户意图
  -> AI 任务规划
  -> 工具路由的计算设计
  -> 按证据排序的变体 / 通路 / 构件
  -> 报告与实验交接
  -> 测试结果记忆,供下一轮设计使用
```

长期产品目标是让合成生物学设计具备"科学操作系统"的体验:

- **设计(Design):** 对通路、酶、结构、元件与宿主背景进行推理。
- **构建(Build):** 生成构件级建议、密码子优化序列、CRISPR 编辑方案与表达
  调控选择。
- **测试(Test):** 组织仿真输出、验证假设与测试方案。
- **学习(Learn):** 将决策、失败案例、实验反馈与基因组学证据保留为可复用的
  项目记忆。

因此,庄周最准确的描述是:

> 一个面向酶与通路工程的原生 AI DBTL 工作台。

## 要解决的问题

合成生物学项目常常败在"想法"与"实验台"之间,因为设计证据分散在互不兼容的
层级里:

- 通路选择与酶的可行性评估相互脱节;
- 酶突变的提出缺少结构或分子动力学层面的依据;
- 表达元件的选择未考虑代谢负担与宿主约束;
- 密码子优化脱离了通路层面的设计意图独立运行;
- 湿实验设计方案需要手动从笔记、脚本与零散的数据库检索中拼凑出来。

庄周的目标是把这些碎片整合成一条可追溯的设计闭环。用户不应该为了回答一个工程
问题,就需要手动在文献检索、序列分析、结构查看、对接、分子动力学、通量平衡
分析、密码子优化、CRISPR 设计、质粒元件选择与报告撰写之间来回切换。

它被设计用来支持的典型问题包括:

- 针对大肠杆菌或酵母中的目标代谢物,应该改造哪条通路?
- 哪些酶可能是瓶颈、毒性节点,或表达效果不佳的靶点?
- 哪些活性位点或稳定性突变值得优先测试?
- 哪种启动子、RBS/Kozak、终止子与整合策略的组合,能匹配期望的表达强度?
- 一段蛋白质序列应该如何针对生产底盘进行密码子优化?
- 应该向实验团队交付一份怎样的证据包?

## AI 原生的 DBTL 工作流

在庄周里,设计&ndash;构建&ndash;测试&ndash;学习(DBTL)是一套可执行的工作流,
而不是一张概念图。

| DBTL 阶段 | AI 角色 | 确定性工具 |
| --- | --- | --- |
| 设计(Design) | 拆解生物学目标、选择分析方法、对不确定性排序 | 通路搜索、FBA/FVA、蛋白质背景信息、突变富集、对接、分子动力学、量子化学 |
| 构建(Build) | 把设计转化为构件级方案 | 启动子/RBS/Kozak 选择、密码子优化、CRISPR 引导设计、整合策略 |
| 测试(Test) | 准备验证假设与可测量的输出 | 实验方案清单、仿真指标、报告生成、结果格式 |
| 学习(Learn) | 保留哪些方案有效、哪些失败及其原因 | 项目记忆、执行历史、知识背景、下一轮排序 |

这让庄周更接近一个科学工作流智能体,而不是问答助手。AI 层的价值在于它能决定
调用哪些工具、如何解读中间结果,但整个工作流始终建立在可核查的输出之上。

## 系统范围

庄周被组织成一套模块化的计算技术栈,而不是单一模型的外壳。

| 层级 | 模块 | 作用 |
| --- | --- | --- |
| AI 控制层 | `nlp`, `agents`, `commands`, `ui` | ReAct 式规划、工具路由、专家提示词、CLI/REPL 交互 |
| 蛋白质与酶设计 | `mutation_enricher`, `mutagenesis`, `molecularconformer`, `enzyme_specificity` | 突变注释、结构背景信息、构象生成、酶特异性检查 |
| 分子建模 | `smartdocking`, `gromacs_md`, `amber_md`, `CYPamber`, `cypforge`, `cypforge_core`, `nonstandard_res`, `qm_engine` | 对接、分子动力学、CYP/血红素流程、CYPForge 血红素-配体前处理检查、非标准残基处理、QM 预检与分析 |
| 合成生物学 | `synbio`, `codon_opt`, `workflow_options` | 元件选择、Assembor 风格酵母启动子/终止子候选、CRISPR 引导设计、密码子优化、表达平衡、设计打包 |
| 代谢推理 | `metakg`, `brain`, `huizi` | 基因组尺度模型/FBA 接口、GraphRAG/知识背景、会话级蛋白质上下文 |
| 基因组学计算 | `genomics` | 基于 VCF/PLINK 的群体基因组学命令规划、样本表校验、多样性/Fst/PCA/ADMIXTURE/TreeMix/IQ-TREE 对接 |
| 报告与记忆 | `report`, `memory`, `workflow` | 结构化报告、项目记忆、可复用的工作流模板 |

## 智能体架构

庄周的核心是把"推理"与"执行"分离开来。

```text
自然语言请求
    |
    v
AI 规划器 / 路由器
    |
    v
领域技能图
    |
    +-- 通路与 FBA 工具
    +-- 酶突变与结构工具
    +-- 对接 / 分子动力学 / 量子化学工具
    +-- 密码子 / CRISPR / 元件工具
    +-- 报告与记忆工具
    |
    v
可审计的设计方案
```

系统可以作为纯 Python 包在不接入大模型的情况下使用,但 AI 接口的意义在于让
多步骤设计工作更自然:科学家陈述生物学目标,智能体负责组装相应的计算路径。

## 认知架构

庄周的智能体系建立在智能体路由图之外的三大支柱之上。

### 双记忆机制：长期知识 + 短期环境

| 记忆类型 | 存储方式 | 作用 |
| --- | --- | --- |
| **长期记忆** | 跨学科知识图谱 | 稳定、可复用的知识 — 蛋白质序列↔结构↔功能关系、酶催化反应与EC分类、代谢通路、菌株改造与表型结果、文献证据、历史任务结果与失败分析 |
| **短期记忆** | 会话上下文与环境状态 | 动态任务追踪 — 当前设计目标、已尝试突变、工具运行状态、模拟结果、候选排名、冲突与不确定性、待执行任务 |

长期记忆回答"系统过去知道什么"，短期记忆回答"系统当前正在做什么"。
决策在两者之间动态融合——既有来自积累知识的连续性，又有适应当前环境的灵活性。

### 决策—执行—审查分离

```
思考 → 行动 → 观察 → 复盘 → 更新后的思考
```

- **决策智能体**: 当前最关键的问题是什么？应调用哪些工具？当前结论的不确定性
  有多大？应扩大搜索还是收敛到少量候选？
- **执行智能体（×n）**: 多个专家智能体并行工作——同时扫描突变位点、对接底物、
  运行分子动力学、分析代谢干预组合。横向扩展形成并行科研计算能力。
- **审查智能体**: 独立于设计的评估角色——结论是否有充分证据？工具结果是否相互
  矛盾？模拟参数是否合理？是否存在过拟合或虚假高分？

这种分离模拟了科学中的同行评议机制，降低了单一模型自我确认偏差的风险。

### 层级化可组合技能体系

技能按层级组织，而非平铺的工具箱：

| 层级 | 类型 | 示例 |
| --- | --- | --- |
| **L1 — 原子技能** | 单一工具操作 | 序列检索、多序列比对、结构预测、分子对接、MD模拟、FBA |
| **L2 — 复合技能** | 多步骤例程 | 活性位点识别 + 突变扫描 + PLM预筛 |
| **L3 — 工作流** | 完整设计流水线 | 酶活性优化：识别位点→生成变体→对接→MD→排序 |
| **L4+ — 元工作流** | 跨领域编排 | 多酶级联设计、全通路优化、酶↔代谢联合设计 |

高层级调用低层级，工作流本身可以成为更复杂系统的子模块。新能力可以通过组合
已有技能来扩展，无需重新训练基础模型。

### 策略涌现

通过跨学科知识图谱推理和多智能体协作，系统可能发现超出预设工作流的新策略——
例如同时改造活性位点与底物通道、通过降低竞争酶活性而非一味提高目标酶活性来
增产、将稳定性优化与表达调控联合设计、或在分子设计前先改变宿主代谢背景。

## 第一性原理酶设计与代谢景观

### 超越序列统计

传统AI蛋白质设计能生成"像蛋白质"的序列，但不一定真正理解催化反应的物理化学
机制。庄周从第一性原理出发——从化学反应本身进行推理：

- 目标反应需要怎样的催化机理？
- 哪些氨基酸应构成催化位点，应满足什么几何关系？
- 底物、过渡态和辅因子应如何排列？
- 哪些突变能降低反应能垒，同时兼顾活性、稳定性、选择性和可表达性？

最终目标是建立自动化流程：
**反应定义 → 催化机制推理 → 活性中心设计 → 骨架与序列生成 → 多尺度模拟 →
变体筛选 → 进化优化**

### 代谢景观引导的代谢工程优化

单个酶性能提升并不必然带来细胞产量提升。细胞内还存在上下游通量不匹配、底物
竞争、辅因子不足、中间产物毒性、能量和还原力限制、调控反馈、生长与合成的
矛盾等多重约束。

庄周通过构建**代谢景观**——从细胞设计变量（酶序列、表达水平、敲除组合、辅因子
供给、培养基组成）到系统表型（产量、速率、得率、生物量、副产物、稳定性）的高维
映射——将代谢工程转化为多目标搜索问题，识别高性能区域、可达路径和组合干预策略。

### 跨尺度协同设计

关键创新在于酶设计与代谢优化之间的**双向链路**：

```
酶序列突变 → 动力学参数变化
  → 代谢通量重分布 → 细胞表型变化
                         ↓
代谢瓶颈分析 ← 目标酶指标
  ← 酶设计约束条件
```

酶设计模块告诉代谢系统"这个突变对动力学有什么影响"；代谢景观告诉酶设计模块
"哪个酶才是真正的瓶颈，需要什么样的动力学改进"。这形成了分子尺度与细胞尺度
之间的闭环。

## 合成生物学能力

庄周目前专注于面向酶与通路工程的早期实用设计支持。每个方向的完整说明见
[Wiki:核心能力](../../wiki/Capabilities-zh)。

- **通路与宿主设计** — 面向大肠杆菌与酿酒酵母的基因组尺度模型接口、通量
  平衡/可变性分析、基因必需性判定,以及连接目标产物与可行宿主干预方案的
  通路搜索。
- **遗传元件选择** — 精选的启动子/RBS/Kozak/终止子库、Assembor 风格的酿酒
  酵母启动子/终止子表,以及用于平衡组装的表达强度匹配。
- **CRISPR 与扰动设计** — 支持 NGG PAM 的 SpCas9 引导序列搜索、基因敲除/
  CRISPRi 辅助工具,以及 HDR 模板设计工具。
- **密码子优化** — 面向毕赤酵母的优化引擎,安装 DNAchisel 时作为后端,并有
  GC 含量与序列规避约束。
- **基因组学计算** — VCF/群体分组文件的输入检查,以及多样性、Fst、PCA、
  ADMIXTURE、TreeMix、IQ-TREE 的可审计命令方案。
- **酶工程** — 结合结构、相对溶剂可及性、活性位点距离、文献证据的突变富集
  分析,对接/分子动力学/量子化学排序,以及通过 CYPForge 提供的感知
  CYP/血红素结构的 Amber 与 GROMACS 支持。

## 技术亮点

- **AI 原生,但依托真实工具。** 大模型负责规划与协调;科学输出由 Python
  模块、数据库接口、仿真引擎或结构化模型计算得出。
- **面向 DBTL 的记忆设计方向。** 系统旨在让设计依据、执行历史与未来的测试
  结果在多轮之间保持关联。
- **可插拔的模型层。** Claude、OpenAI 兼容接口、DeepSeek 兼容端点,以及本地
  Ollama 风格后端均可作为可选的规划模型。
- **环境隔离。** 本机工具、WSL 工具、conda 环境与远程 SSH 计算资源可独立
  配置。
- **感知基因组学的 DBTL 反馈。** VCF/PLINK 工作流被表示为带样本校验、质控
  参数与方法说明的可核查命令方案,而不是不透明的 notebook 片段。
- **默认注重隐私。** API 密钥、主机路径、SSH 配置与大体积模型文件均外部化
  存放,并被 Git 忽略。
- **可复现的打包方式。** 源码分发包排除缓存、日志、本地凭证、私有存储导出
  文件与大体积检查点。
- **结构化报告。** 设计输出可转换为 Word 风格报告以及可复用的项目记忆记录。

## 核心创新

1. **从单模型预测到自主科研系统。** 不是更好的评分函数——是一个能任务分解、
   工具选择、并行执行、结果审查、动态重规划、持续积累知识的系统。

2. **知识图谱驱动的长期记忆。** 每个设计决策可追溯、有证据链。失败策略与成功
   结果一起存储——系统学到的不只是"什么失败了"，更是"为什么失败"。

3. **双记忆架构。** 稳定的长期知识 + 动态的短期环境上下文，在决策时融合，
   既有连续性又有适应性。

4. **决策—执行—审查分离。** 独立审查机制类似科学同行评议，降低单一模型
   自我确认偏差的风险。

5. **层级化可组合技能体系。** L1原子技能→L2复合技能→L3工作流→L4+元工作流，
   支持递归分解与持续能力扩展，不依赖重新训练基础模型。

6. **数据驱动×第一性原理融合。** 蛋白质语言模型负责大规模快速筛选；物理模拟
   负责验证机制可信度。效率与可信度兼顾。

7. **跨尺度酶↔通路↔细胞协同设计。** 打破蛋白质设计与代谢工程之间的传统
   壁垒，形成统一优化框架。

8. **策略涌现。** 通过知识图谱推理与多智能体协作，发现超出预设工作流的新
   干预策略。

9. **可解释、可审计、可复现。** 每个设计候选附带完整证据链：为什么选该位点、
   引用了哪些知识、调用了哪些工具、各步得分、最终决策理由。

## 技术闭环

完整的闭环工作流涵盖七个阶段：

| 阶段 | 内容 |
| --- | --- |
| **1. 问题定义** | 目标反应、底物/产物、宿主细胞、性能指标、计算与实验预算 |
| **2. 知识构建** | 整合文献、蛋白质/结构/代谢数据库、组学数据、历史实验记录 |
| **3. 机理分析** | 反应中心、键断裂与生成、催化基团、辅因子、过渡态特征 |
| **4. 候选设计** | 活性位点方案、蛋白质骨架、突变体、代谢改造靶点、调控策略 |
| **5. 多层筛选** | 规则与知识过滤 → PLM评分 → 结构预测 → 对接 → MD → 能量与催化几何 → 代谢仿真 → 多目标排序 |
| **6. 实验验证** | 优先验证高价值候选；测定酶动力学、稳定性、表达量、产量、速率、得率 |
| **7. 闭环学习** | 结果写回知识图谱；更新突变效应模型、景观模型、工具可靠性权重、智能体策略 |

## 定位总结

庄周是面向合成生物学的专用 AI 科学产品的起点——一个以跨学科知识图谱为认知
基础、以多智能体推理系统为决策中枢、以层级化科学技能（蛋白质设计、分子模拟、
代谢网络分析）为执行工具的自主科学智能体平台，形成**思考→行动→观察→复盘**
的完整闭环。

差异化核心：

- **机理驱动的酶设计**，而非纯序列生成。
- **单酶与代谢网络的跨尺度联合优化**。
- **能够长期积累知识、自主调用工具并通过实验反馈持续进化的闭环科研系统**。

目标不是取代领域科学家，而是给他们一个能够在整个 DBTL 周期里连接推理、工具、
数据与报告的科学操作系统。

简短版本:

> 从生物学意图到可执行的 DBTL 设计——一个会梦见酶的 AI 科学家。
